RUMIK TTS INTEGRATION — ITERATION NOTES (2026-09-18)
=====================================================================

DECISION
---------------------------------------------------------------------
Switched the bot's TTS from OpenAI (gpt-4o-mini-tts, "shimmer") to
Rumik Silk (mulberry model, "adam" voice) — app/main.py _build_tts(),
app/services/rumik_tts.py. Reason: this bot's calls are Hindi/English
code-mixed (Sarvam STT already runs in "codemix" mode); Rumik's
mulberry model is purpose-built for Hindi (Devanagari) + English +
code-mixed text in one request, and was compared directly against
Sarvam's TTS (Bulbul) on the same 10 restaurant-context phrases before
deciding.

WHY NOT SARVAM TTS
---------------------------------------------------------------------
Tested Sarvam Bulbul (v2 -> deprecated mid-test by Sarvam, switched to
v3, speaker "shubh", documented male default) side by side with Rumik
on the same 10 phrases (English/Hindi/code-mixed restaurant lines:
booking confirmation, hours, menu questions, seating). Both were
usable; went with Rumik per user's call after listening to both sets.

VOICES AVAILABLE (Rumik, mulberry model — the only one with male presets)
---------------------------------------------------------------------
Male:   lucas, noah, theo, adam   <- using "adam"
Female: emma, mia, sophia, ava, ira, siya, aisha, zoya
(mulberry-1.6 exists too but only ships 4 female presets — no male
option — so staying on plain "mulberry" for a male voice.)

"TABLE" PRONUNCIATION
---------------------------------------------------------------------
Flagged as unclear ("ununderstandable") in the initial 10-phrase batch.
Rumik has no phoneme/IPA/pronunciation-lexicon override in its API
(checked docs.rumik.ai — normalization.md only covers numbers/dates/
money/IDs, nothing for word-level pronunciation control).

Tested 7 spelling variants of the same carrier phrase ("Your table for
two is ready" / Hindi equivalents): plain English "table", ALL CAPS
"TABLE", manual respelling "tay-bul", three Devanagari transliteration
variants (टेबल / टेबुल / टेयबल), and the pure-Hindi word "मेज़".

Result: plain English "table", ALL CAPS, the "tay-bul" respelling, and
the "टेयबल" Devanagari variant all read clearly. Decision: don't
special-case it — use plain English spelling in code-mixed/English
text, standard "टेबल" transliteration in Hindi text. No code change
made for this; revisit only if it turns into an actual live-call
problem later, with whichever fix is cheapest at that point.

IMPLEMENTATION NOTES
---------------------------------------------------------------------
- app/services/rumik_tts.py: RumikTTSService(TTSService) — pipecat has
  no first-party Rumik integration, so this wraps Rumik's one-shot HTTP
  endpoint (POST https://silk-api.rumik.ai/v1/tts) the same way
  pipecat's own OpenAITTSService/SarvamHttpTTSService wrap their
  providers: one HTTP request per utterance, WAV response parsed via
  Python's `wave` module (not a hardcoded 44-byte header slice) down to
  raw PCM for a single TTSAudioRawFrame.
- Confirmed via a real API round-trip: Rumik's default (no
  audio_format param) response is mono, 16-bit PCM, 24000 Hz, standard
  44-byte WAV header, no extra chunks.
- self.sample_rate resolves to 24000 at pipeline start() because we
  pass sample_rate=24000 explicitly to TTSService.__init__ — verified
  against tts_service.py's start(): `self._sample_rate =
  self._init_sample_rate or frame.audio_out_sample_rate`. Pipecat's own
  transport-output stage handles downsampling to whatever the
  telephony transport needs (8kHz mu-law for Exotel/Plivo/Vobiz) — same
  as how OpenAI TTS (also 24kHz) already worked in production before
  this change.
- RUMIK_API_KEY added to app/config/settings.py, .env.example, and
  (locally) .env — renamed from the ad hoc lowercase `rumik_tts` key
  originally pasted into .env to the project's UPPER_SNAKE_CASE
  convention.
- mulberry's `description` field is required whenever a `speaker`
  preset is also given (Rumik's API rejects speaker-only requests) —
  using: "a male, 30s, indian accent voice, normal pitch, smooth
  timbre, conversational pacing, professional register, like a
  restaurant host" for all TTS output.
